## Findings and resolutions

### Header normalization at position 117

- Finding: the source title is “Gifted-Talented-Indicator-Code” at position 117 (layout page 4), while repository instructions require the shared header `gifted_and_talented_indicator_code` when the source meaning matches.
- Severity: low.
- Resolution: corrected `gifted_talented_indicator_code` to `gifted_and_talented_indicator_code`. The range and source ordinal remain unchanged.
- State: `verified`.

### Official filename pattern

- Finding: the source-backed pattern allowed an unsupported optional timestamp and optional `.txt` extension and did not distinguish the documented region and district basename components. The naming convention states that reporting text files use the same basename as the region or district zip folder and documents preliminary `SP_0326_TELPASALT_..._V##` and final `SF_0326_TELPASALT_..._V##` names (pages 2 and 8).
- Severity: medium.
- Resolution: narrowed the TEA-referenced regex to the documented preliminary/final, region/district, versioned `.txt` basename forms.
- State: `verified` against the naming-convention archive.

Four earlier filename patterns are retained because they are inherited compatibility patterns whose references point to external operational guidance. The assigned layout does not establish those basename forms, they were not independently source-verified in this isolated review, and no operational sample was available. Their retention is not a claim that the 2026 TEA PDFs support them.

The header correction is schema-facing but preserves the source meaning and fixed-width position. Consumers using the former header must update to `gifted_and_talented_indicator_code`; no raw-file reprocessing is required unless a consumer materializes columns by mapping header. The filename regex correction affects file discovery only and does not alter record parsing.
